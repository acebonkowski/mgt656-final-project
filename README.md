# mgt656-final-project

Event discovery app for Yale graduate students (MGT656 final project). Django + PostgreSQL (Supabase), deployed on Render.

Onboarding now shares the authentication profile, seeds provisional Yale degree
choices, and supports private object-storage photos. See
[onboarding setup and release checks](docs/onboarding-development.md), including
the required storage environment variables and `setup_photo_storage` command.

## Local development

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
export DJANGO_DEBUG=true          # SQLite + dev secret key, local only
.venv/bin/python manage.py migrate
.venv/bin/python manage.py seed   # grader accounts (safe to run again)
.venv/bin/python manage.py runserver
```

To use Postgres locally, also export `DATABASE_URL` (see [.env.example](.env.example)).

## Tests

```bash
DJANGO_DEBUG=true .venv/bin/python manage.py test
```

Tests never touch external services: the health check's database failure is mocked, settings tests only parse fake URLs, and login emails are captured in memory by Django's test runner (send failures are mocked).

## Configuration

All configuration comes from environment variables. Nothing secret is committed. [.env.example](.env.example) lists every variable, with placeholders only.

| Variable | Required on Render | Notes |
|----------|-------------------|-------|
| `DATABASE_URL` | yes | Supabase **Session pooler** string (port 5432) |
| `DJANGO_SECRET_KEY` | yes | Generated by the Render blueprint |
| `APP_ENV` | yes | `staging` or `production` (set by the blueprint) |
| `DJANGO_DEBUG` | no | Defaults to `false` |
| `DJANGO_ALLOWED_HOSTS` / `DJANGO_CSRF_TRUSTED_ORIGINS` | no | The Render hostname is added automatically; use these for custom domains |
| `PORT` | set by Render | gunicorn binds to it |
| `TEAM_NICKNAME` | no | Team course nickname; defaults to `holy-dew`. Holds the nickname, never the hash |
| `TEAM_MEMBER_NICKNAMES` | no | Comma-separated member nicknames shown on the A/B page |
| `MAP_API_KEY` | for the map | MapTiler key for the home screen (`/map/`). Visible in page source by design, so restrict it to our domains (see below). If empty, `/map/` shows a "map isn't available" message. |
| `RESEND_API_KEY` | for login emails | Resend API key, used as the SMTP password. Without it, deployed environments don't send codes (students see an error); local development prints emails to the terminal |
| `EMAIL_FROM` | for login emails | Sender on the team's verified Resend domain, e.g. `Yale Events <login@mail.<domain>>` |
| `EMAIL_PORT` | no | Defaults to `587`; Resend also accepts `2587` |
| `GRADER_FIXED_OTP` | for grader login | Fixed 6-digit code for the seeded grader accounts. Same value on staging and production. Never commit it |

## A/B test page

The course-required A/B page lives at `/` + the first 7 hex characters of `sha1(TEAM_NICKNAME)`, hashed with no trailing newline (`printf %s holy-dew | shasum`, **not** `echo`). For `holy-dew` that's:

- Page: `/e75d81f`. Each new visitor gets `kudos` or `thanks` (50/50, kept in the session). One impression is counted per visitor and at most one click.
- Stats: `/e75d81f/stats`. Live JSON with counts and `preferred`, the variant with the higher click rate. With no data or a tie, `preferred` is `kudos`.

The code is in [abtest/](abtest/). Impressions and clicks can be viewed (and test visits deleted) in the Django admin under **A/B test**.

## Login (`/login/`)

Students log in with a one-time code emailed to their Yale address (#6); there are no passwords. It's built on Django's normal auth and sessions; the code is in [accounts/](accounts/).

- `/` sends logged-out visitors to the **Welcome** screen (`/login/`) and logged-in users to the map.
- Only `@yale.edu` addresses and its subdomains (e.g. `@som.yale.edu`) are accepted, checked on the server.
- Codes are 6 digits, valid for 10 minutes, work once and stop working after 5 wrong tries. Only a keyed hash is stored. A new code can be sent after 45 seconds (enforced on the server).
- A new address creates an account and goes to onboarding (`/onboarding/`, a placeholder until #7). An existing user with a completed profile goes to the map.
- Log out with the button on the map.

### Grader accounts and the seed command

`python manage.py seed` creates or updates the grader accounts. It's safe to run more than once; run it after every database reset and after the first deploy of an environment:

| Account | Role |
|---------|------|
| `kyle.jensen@yale.edu` | Admin (staff + superuser, can open `/admin`) |
| `mgt656-demo-member@yale.edu` | Member (regular student) |

Graders log in on the Welcome screen with the fixed code from `GRADER_FIXED_OTP` (per Kyle). They never receive email, the code works for no other address, and 5 wrong tries lock the address for 15 minutes. The accounts have no password: `/admin`'s login page redirects to the Welcome screen, and Kyle's account opens `/admin` once logged in.

On Render the seed runs automatically on every start, right after `migrate` ([bin/start.sh](bin/start.sh)), so a restart re-creates the accounts after a database reset. To run it by hand, run `python manage.py seed` with that environment's `DATABASE_URL` exported.

### Email (Resend)

Codes are sent through Resend's SMTP relay using Django's built-in SMTP backend (`smtp.resend.com`, user `resend`, the API key as the password). Resend only delivers to any address from a **domain the team controls and has verified** (SPF/DKIM DNS records), so `EMAIL_FROM` must use that domain.

## Home screen map (`/map/`)

`/map/` is the logged-in home screen: a dark New Haven map with the headline "More coming soon." (#8). Logged-out visitors are sent to the Welcome screen (`LOGIN_URL`). `LOGIN_REDIRECT_URL` and `ONBOARDING_SUCCESS_URL` both point to `map`.

The map is drawn in the browser by [MapLibre GL JS](https://maplibre.org/) (open source, pinned to 5.24.0 from unpkg with Subresource Integrity hashes) using MapTiler's `dataviz-dark` style, tinted blue-black to match the page. The map code is kept in two files:

- [templates/core/_map_provider.html](templates/core/_map_provider.html) loads MapLibre and the provider script. It's only included when `MAP_API_KEY` is set.
- [core/static/core/map_provider.js](core/static/core/map_provider.js) defines `window.renderMap(element, config)`. It builds the MapTiler style URL from the key, centres the map on New Haven and applies the blue-black tint.

The provider-neutral [core/static/core/map.js](core/static/core/map.js) calls `renderMap`. It shows the fallback message if there's no key, if MapLibre didn't load, if the browser has no WebGL, or if MapTiler rejects the key (HTTP 401/403).

The server never calls MapTiler: the browser fetches the style and tiles directly. Tests only use a fake key, and `NoNetworkTests` fails if rendering the page opens any network connection.

### Getting a MapTiler key

1. Sign up at [cloud.maptiler.com](https://cloud.maptiler.com/) (the free plan needs no credit card).
2. Go to **Account → API keys**. The free plan allows **only one key**, so local development, staging and (later) production all share it.
3. **Restrict the key to our domains** in its settings, under **Allowed HTTP origins**:
   - `localhost` and `127.0.0.1` (local development)
   - `mgt656-final-project-staging.onrender.com` (staging)
   - the production `onrender.com` hostname, once that service exists

   A restricted key is rejected (HTTP 403) on any other site, so a copied key is useless elsewhere. The exception is localhost: anyone running the app locally with our key could use it, so share the key only within the team. The map page sends our origin to MapTiler (`<meta name="referrer" content="strict-origin-when-cross-origin">`) so the restriction can be checked; Django's default `same-origin` policy would send nothing.
4. In Render, open the service, go to **Environment**, and set `MAP_API_KEY` to the key. Saving restarts the service.
5. To test locally, set the key in the same terminal as `runserver` (the app doesn't read `.env` files):
   - macOS/Linux: `export MAP_API_KEY=<key>`
   - Windows PowerShell: `$env:MAP_API_KEY = "<key>"`

Because the key is shared, revoking or regenerating it breaks the map everywhere at once. If it ever leaks, regenerate it in MapTiler and update `MAP_API_KEY` in Render and in each teammate's shell.

Never commit a key, not even the local one. Keep it in your shell or in Render only. The free plan requires the MapTiler and OpenStreetMap attribution, which MapLibre shows in the bottom-right corner; don't hide it.

## Deploying (staging and production)

- **Staging:** https://mgt656-final-project-staging.onrender.com (health check: [/healthz](https://mgt656-final-project-staging.onrender.com/healthz))

[render.yaml](render.yaml) defines two free web services, `mgt656-staging` (auto-deploys on every push to `main`) and `mgt656-production` (manual deploys only). On every start, [bin/start.sh](bin/start.sh) runs `migrate`, then `seed`, then gunicorn on `$PORT`, with access and error logs going to stdout. Render's pre-deploy command needs a paid plan, so migrations run at start instead.

One-time setup (done by a team member with the accounts):

1. **Supabase:** create two projects, e.g. `mgt656-staging` and `mgt656-production`, in region **West US (Oregon)** (us-west-2), the same region as the Render services. For each one, go to **Connect** and choose **Session pooler**, then copy the URI (`postgresql://postgres.<ref>:<password>@aws-1-us-west-2.pooler.supabase.com:5432/postgres`).
   - Use the session pooler, not the direct connection. Render has no outbound IPv6, and Supabase's direct host is IPv6-only unless you buy the IPv4 add-on.
2. **Render:** go to **New**, then **Blueprint**, and select this repo. When prompted, paste each service's own `DATABASE_URL`: the staging URL into `mgt656-staging` and the production URL into `mgt656-production`.
3. Open `https://<service>.onrender.com/healthz`. It should return `{"status": "ok", "database": "ok"}`.

`/healthz` is also Render's health check. It returns `503` if the database can't be reached, so a deploy with a bad `DATABASE_URL` won't go live.
